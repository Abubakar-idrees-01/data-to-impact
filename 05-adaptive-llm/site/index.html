Tiny GPT, trained on a laptop, running in your browser

Six-layer transformers built and trained from scratch on a 2015 laptop CPU (project 5 of data-to-impact), on 12 million tokens of children's stories. Nothing is sent to a server: the weights load into this page and every token is computed here, in plain JavaScript. Give it the start of a story. Code and docs.

0 = always the most likely word; higher = more surprising.

Each layer has its own exit. A token stops at the first layer whose top word is at least τ likely; the skipped layers still get keys and values (CALM), so later words can look back at it.

Mixture-of-Experts

The MoE model replaces each feed-forward network with 8 smaller experts, and a router sends every token to 2 of them. That gives 2.6× the parameters at the same compute per token. It reached perplexity 8.3 against the dense model's 9.3. Colour by "expert" to see where the router sends each token.

How it works, and the routing bug it found

Early exit

The early-exit model can answer after any layer. Turn on "leave early" and watch "layers per token" drop. Then watch "compute vs full model": checking confidence means projecting onto all 4,096 words, which costs more than a layer. So above τ ≈ 0.4 the checks cost more than the layers they save, which is exactly what the measurements found.

The measurements

What it can and can't do

It writes short, grammatical stories with dialogue, because that is all it has ever read. It loses track of names and objects within a few sentences, and it cannot answer questions or chat. Weights are 8-bit (one scale per row), which raised the validation loss by 0.0001–0.0004.
